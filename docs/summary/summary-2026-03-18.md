# Summary 2026-03-18: Perbaikan UI Undian Doorprize & Multi-Select Hadiah

Pada sesi ini, beberapa perubahan telah diimplementasikan terhadap fitur pengundian Doorprize di tab Admin, mencakup perubahan *schema* di backend hingga integrasi UI yang lebih dinamis.

### Poin Detail:
1. **Pengembalian Skema `event_prizes` (Backend & Model)**:
   - Membuat skrip migrasi log relasi untuk membuat tabel `event_prizes` dan mengaitkannya dengan `event_winners` via field `prize`.
   - Mengupdate model `EventWinnerModel` beserta entitasnya dan `EventPrizeModel` untuk mengakomodir relasi baru.

2. **Penyesuaian UI Manajemen Hadiah (`DoorprizeTab`)**:
   - Memunculkan ulang panel input nama dan kuantitas hadiah yang akan diundi.
   - Hadiah yang dimasukkan akan masuk ke data relasi PocketBase.
   - Daftar riwayat pemenang (winners) dikelompokkan dengan elegan berdasarkan nama hadiah.
   - Ditambahkannya fitur UI untuk mendiskualifikasi dan menghapus data pemenang secara permanen (melalui dialog konfirmasi).

3. **Multi-Select Hadiah di Halaman Pengacakan (`AdminEventRafflePage`)**:
   - Telah ditambahkan pustaka `multi_select_flutter` untuk memilih beragam jenis hadiah secara massal sekaligus.
   - Dropdown untuk menetapkan jumlah pemenang dirubah menjadi otomatis hitung dari jumlah total hadiah (kuantitas) *selected item* dari Multi Select component, maksimal kuota penarikan sekaligus dibatasi 10 pemenang.
   - Logika simulasi animasi tiket dikembangkan agar menetapkan mapping hadiah tepat kepada masing-masing Card Grid tiket berdasarkan jumlahnya.
   - Desain Grid Item tiket kini memunculkan *badge text* nama tipe hadiah pada masing-masing pemenang ketika undian usai.
   - Tombol operasional seperti **"UNDIAN BARU"** dirapikan ukurannya untuk *clear history* grid. Khusus untuk nama peserta via *coordinator (manual purchase)* otomatis dilabeli `(Koor) Nama`.

4. **UI Refinements & Bug Fixes Tambahan**:
   - Memperbaiki error `Unsupported Operation: Infinity or NaN toInt` yang terjadi ketika layout mencoba melakukan *render grid* tanpa adanya pemenang/hadiah yang di-set.
   - Kolom "Pilih Hadiah" dirubah menjadi desain Horizontal agar sejajar dengan kolom Durasi dan Jumlah Pemenang.
   - Membuang library `multi_select_flutter` dan menggantikannya dengan dialog Custom bawaan Flutter untuk menyematkan *logic* penghitungan kustom di Popup.
   - Sisa target kuota hadiah dimasukkan kembali ke *UI logic Popup Daftar Hadiah* dengan menampilkan teks `Sisa: X / Total`.
   - Kuota pemenang dilimitasi ke limit absolut 10 maksimal per roll. Popup juga divalidasi dengan memunculkan `SnackBar` jika pemilih hadiah berusaha menceklis kotak melebihi limit maksimal tersebut.

5. **Logika Diskualifikasi & Partial Re-roll**:
   - Limit hadiah dan pengkalkulasian barang yang 'diklaim' (`claimed`) telah disempurnakan. Kalkulasi sekarang hanya menghitung entitas di dalam database PocketBase yang memiliki `status == 'won'`. Jika pemenang didiskualifikasi (atau dibatalkan), nilai stok barang `Sisa:` otomatis diperbarui dan kembali bertambah.
   - Menghidupkan ulang logika pengacakan di mana tombol *Acak Lagi* memiliki validasi. Tombol ini hanya akan bisa ditekan usai grid pemenang dirender JIKA minimal ada 1 tiket yang didiskualifikasi (`isDisqualified`).
   - Melakukan fitur *Partial Re-roll*: Saat mencari pengganti untuk peserta yang didiskualifikasi, sistem tidak menghapus dan mereset tiket pemenang lama yang sah, melainkan secara spesifik memutar ulang kartu *placeholder* pada urutan mereka berkesesuaian di grid untuk menaruh peserta baru ke dalam slot beserta nama hadiah lama secara otomatis. Bug Exception tipe Null List juga sudah diatasi pada logika internal pergantian tiketnya.
